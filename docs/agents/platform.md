## Overnight run (runbook)
- **Before:** the pipeline has passed end to end on 3 real rulings; the capacity floor says the run fits; the 70B is warmed up; the owner, machine, key and concurrency share are written in `docs/STATE.md`.
- **During:** the queue lives in Postgres (items `todo`, `done`, `failed`); the night's load is unmeasured (D-028), so a sentinel batch runs every 30 minutes and a rising error rate stops the run; the limiter backs off on 429/504; a circuit breaker pauses the run and leaves items `todo`, never `failed`. Every raw output goes to `llm_calls`.
- **Checkpoints:** counters per stage and language every 30 minutes in a log file; a stage with zero output stops the run.
- **Resume:** rerun the same command; done items are skipped, answered calls come from the cache.
- **Morning:** compare counters with the population size; list `failed` items with reasons; rerun them once; record the result in `docs/STATE.md`.

## Rules specific to this role
- No network call at import or start-up; `make smoke-llm` and `make warmup` are explicit.
- No default values for `LLM_*` in live mode (D-032 says what replay mode needs).
- The served model is checked against the allow-list of G3 (the Apertus v1.5 ids of `MODELS.md` in both forms, as the probe recorded them, plus the `LLM_NAME` the runner set if it names an Apertus model), not by exact string match with the requested id. A missing `x-keera-model` header is logged, not fatal.
- Never commit anything from `data/private/` or, while D-031 is open, `data/derived/`; add the private-content guard of D-031 to pre-commit once it is settled.
- Template files are never renamed or moved (D-039); never deleted (our rule, D-044). Never edit `judgements/`, the pitch PDF or `challenge_description.md` (our rule, D-040, D-044). Append to `.gitignore`, never replace it (our rule, D-044).
- `llm_calls`, caches and logs never hold an author field, staff code or intranet link from `judgements/` (D-051).
